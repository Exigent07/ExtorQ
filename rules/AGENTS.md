# rules/AGENTS.md: detection rules (owner C2)

Scoped guide for `rules/`. Canonical project guide: `/AGENTS.md`. Engine reference:
`docs/detection-engine.md`. Rule catalog: `docs/detection-catalog.md`.

## Layout

```
rules/<domain>/<RULE-ID>.yaml      metadata (maps 1:1 onto contracts.alert.RuleMetadata)
rules/<domain>/<RULE-ID>.sql       one ClickHouse SELECT / WITH ... SELECT
rules/<domain>/tests/<RULE-ID>/*.jsonl   fixtures (SecurityEvent lines or ingest records)
```

Domains: `linux`, `kubernetes`, `github`, `http`, `macos`, `correlation`.

## Non-negotiable

1. **Real fields only.** Use only fields the producers genuinely populate: the catalog's
   `key_fields` (`backend/src/extorq/contracts/catalog.py`) and the producers' notes in
   `docs/team/interface-changes/`. Unknown stays unknown: never `coalesce` a missing value
   into something that looks like telemetry.
2. **Parameters only.** Values reach SQL as server-side placeholders `{name:Type}`; window
   bounds `{window_start:DateTime64(3, 'UTC')}` / `{window_end:DateTime64(3, 'UTC')}` are
   mandatory. No string building, no `SETTINGS`, no table functions, no tables outside
   `events, assets, inventory_items, finding_observations, scan_runs, simulation_runs`.
   `extorq rules validate` enforces this; the readonly ClickHouse identity
   `extorq_rules_ro` is the real boundary.
3. **Duplicate-safe.** `LIMIT 1 BY event_id` on every input, `uniqExact` for counts. Rows
   in `events` can be duplicated until ReplacingMergeTree merges.
4. **Never filter simulation telemetry.** `extorq-sim-<run_id>` marks genuine telemetry.
5. **Confidence = evidence completeness** (e.g. two independent sources agree, source IP
   attributable), never a maliciousness guess. Shared NAT/gateway sources
   (`10.0.2.2`, `172.18.0.1`, `10.244.0.1`, loopback) lower attribution.
6. **Correlation rules state co-occurrence, not causation** (see CORR-002).
7. **Untrusted text.** Log lines, routes, user names, object names are attacker
   controlled: bound them (`substring`), never interpret them; summary templates use
   `{placeholder}` only and values are sanitised by the engine.
8. **Tests.** Every rule has positive and negative fixtures plus false-positive and blind-spot
   notes. Fixtures are synthetic and labelled (`labels: {"extorq.fixture": "synthetic"}`),
   generated by `tests/rules/generate_fixtures.py` (deterministic), or derived from
   captured real records with the producer's own normaliser (`derived-captured`, see
   `tests/rules/captures/README.md`). A case can assert exact `features` values and
   `summary_contains` substrings; use them to prove *why* a row alerts (for example that a
   deletion is context, not evidence).
9. **Allowlist evidence, fail closed.** Decide what counts as evidence with an allowlist of
   known-good shapes (CORR-002/VM-002 `change_syscalls`), not a denylist of known-bad ones:
   an unrecognised value must not count. Exceptions for expected platform behaviour must be
   narrow, deterministic and tested on both sides (K8S-002's bootstrap exception: identity
   AND exact object AND time anchor); never a name-prefix allowlist.

## Workflow

```bash
uv run extorq rules validate                          # static validation
uv run python tests/rules/generate_fixtures.py --only <builder>   # (re)generate fixtures
uv run pytest tests/rules -q                          # ephemeral ClickHouse harness
uv run python -m extorq.detection.dryrun --rule <ID> --start <UTC> --end <UTC>  # live data, read-only
docker compose --profile full restart detector        # load changed rules (owner C2)
```

Rule identity (`alert_id`) excludes the rule version: bump `version` (semver) for any
logic change; open alerts are extended, not duplicated. Stored alerts keep the evidence and
summary their version wrote (append-only); check a change against stored telemetry with the
dry run before deploying it. Update `docs/detection-catalog.md` in the same change.
