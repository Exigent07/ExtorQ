## 1. Lab web app log contract (`lab-portal`, schema `lab-portal.log.v1`) — FINAL

Consumers: **A** (gateway OTLP path via B2's `otlp_k8s.py`), **B2** (container
image + normaliser), **B1** (Linux collector). Source:
`lab/apps/lab-portal/app.py` (Python 3 stdlib only, configured by env vars).

The app writes exactly **one JSON object per line to stdout**. Every key is
always present (unknown values are `null`); no other keys are ever emitted.
stderr carries only human-readable startup diagnostics, never events.

| key | type | meaning |
|---|---|---|
| `ts` | string | RFC 3339 UTC, millisecond precision, `Z` suffix, e.g. `2026-11-21T10:04:02.123Z` |
| `level` | string | `info` \| `warning` \| `error` |
| `service` | string | always `lab-portal` |
| `event` | string | `auth.login_failed` \| `auth.login_succeeded` \| `authz.denied` \| `http.request` |
| `user` | string \| null | submitted login name (sanitised, ≤ 64 chars) or session user; `null` if none |
| `src_ip` | string \| null | client IP: `X-Real-IP` **only** when the TCP peer is a trusted proxy (default `127.0.0.1`), otherwise the TCP peer address; `null` if a trusted proxy sent an invalid value |
| `request_id` | string \| null | `X-Request-ID` from a trusted proxy (nginx `$request_id`, 32 hex) or a generated UUID4 hex |
| `request_id_source` | string | `propagated` (from trusted proxy) \| `generated` (by the app) |
| `method` | string | HTTP method (≤ 16 chars) |
| `route` | string | request path **without query string or fragment** (≤ 512 chars) |
| `status` | int | HTTP status returned |
| `reason` | string \| null | machine reason (see below), `null` for successes and plain access lines |
| `user_agent` | string \| null | `User-Agent` header (≤ 512 chars) or `null` |
| `duration_ms` | float \| null | handler duration in milliseconds (3 decimals) |

Events:

* `auth.login_failed` (`warning`, POST `/login`): reasons `unknown_user`,
  `invalid_password`, `missing_credentials`, `malformed_body`,
  `body_too_large`, `unsupported_media_type`, `login_disabled` (no credential
  configured: the app fails closed). Status 400/401/413/415.
* `auth.login_succeeded` (`info`, POST `/login`): status 200 (JSON) or 303 (form).
* `authz.denied` (`warning`, GET `/admin` without a valid session): status 401,
  reasons `missing_session`, `invalid_session`, `expired_session`.
* `http.request`: one line per request **only when `LOG_ACCESS=1`** (k8s). On
  the VM nginx logs access instead (`LOG_ACCESS=0`). Level `info` (< 400),
  `warning` (4xx), `error` (5xx). `/healthz` is skipped unless
  `LOG_ACCESS_HEALTHZ=1` (probe noise).

Passwords are never logged. The app never echoes request data into HTML.

Mapping used by the Linux collector (recommended for `otlp_k8s.py` too):
`event_type = "app." + event` for `auth.*`/`authz.*` (`app.auth.login_failed`,
`app.auth.login_succeeded`, `app.authz.denied`) and `http.request` unchanged;
`actor.name=user`, `network.src_ip=src_ip`, `http.request_id=request_id`
(set only when `request_id_source == "propagated"`, because a generated id is
not a cross-component correlation key; keep the generated one in
`attributes.app_request_id`), `http.route=route`, `http.method=method`,
`http.status_code=status`, `http.user_agent=user_agent`,
`http.duration_ms=duration_ms`, `attributes.reason=reason`,
`event_time=ts`, outcome `failure`/`success`/`denied`.

Environment variables: `LAB_PORTAL_HOST` (default `127.0.0.1`),
`LAB_PORTAL_PORT` (`8080`), `LOG_ACCESS` (`0`), `LOG_ACCESS_HEALTHZ` (`0`),
`LAB_PORTAL_TRUSTED_PROXIES` (`127.0.0.1`, comma separated IPs),
`LAB_PORTAL_DEMO_USER` (`lab-admin`), `LAB_PORTAL_PASSWORD_HASH_FILE`
(PBKDF2 hash file, preferred) or `LAB_PORTAL_PASSWORD_FILE` (plain text file,
compared in constant time), `LAB_PORTAL_SESSION_TTL` (`3600`),
`LAB_PORTAL_COOKIE_SECURE` (`0`), `LAB_PORTAL_MAX_CONCURRENCY` (`32`).
For k8s (B2): run with `LAB_PORTAL_HOST=0.0.0.0 LOG_ACCESS=1`, mount the demo
credential from a Secret as a file and point `LAB_PORTAL_PASSWORD_FILE` (or
`LAB_PORTAL_PASSWORD_HASH_FILE`) at it. `GET /healthz` is the probe endpoint.

## 2. `packages` dispatch output (consumer: **C3**, Trivy SBOM scanning)

Obtained with `SSHDispatchClient(config).run("packages")` from
`extorq_collectors.linux.ssh` (see section 3). Shape (`extorq.linux.packages.v1`):

```json
{
  "type": "packages",
  "protocol": 1,
  "schema": "extorq.linux.packages.v1",
  "collected_at": "2026-11-21T10:04:02.123Z",
  "hostname": "lab-vm-01",
  "os_release": {"ID": "ubuntu", "VERSION_ID": "24.04", "VERSION_CODENAME": "noble",
                  "PRETTY_NAME": "Ubuntu 24.04.3 LTS", "NAME": "Ubuntu", "ID_LIKE": "debian",
                  "UBUNTU_CODENAME": "noble", "VERSION": "24.04.3 LTS (Noble Numbat)"},
  "dpkg_architecture": "arm64",
  "packages": [
    {"name": "openssl", "version": "3.0.13-0ubuntu3.5", "architecture": "arm64",
     "source_name": "openssl", "source_version": "3.0.13-0ubuntu3.5", "status": "ii"}
  ],
  "count": 612,
  "truncated": false,
  "errors": []
}
```

* `packages` contains every dpkg package whose status is not `not-installed`
  or `config-files` (`status` is dpkg's 3-letter `db:Status-Abbrev`, trimmed).
* `source_name`/`source_version` come from `${source:Package}`/`${source:Version}`
  (Ubuntu security data is keyed by source package).
* PURL suggestion for CycloneDX:
  `pkg:deb/ubuntu/<name>@<version>?arch=<architecture>&distro=ubuntu-<VERSION_ID>`
  with `upstream=<source_name>` when it differs from `name`.
* `truncated=true` only if more than 20000 packages exist (never on the lab VM).

## 3. Reusable SSH helper (consumer: **C3**)

```python
from extorq_collectors.linux.ssh import SSHDispatchClient, SSHTarget
client = SSHDispatchClient(SSHTarget.from_mapping(cfg["ssh"], base_dir=repo_root))
text = client.run("packages")          # str (UTF-8), raises SSHDispatchError subclasses
raw = client.run_bytes("audit - 0 65536")
client.close()                          # closes the ControlMaster connection
```

Errors: `HostKeyVerificationError` and `SSHAuthenticationError` (never retried),
`DispatchDenied` (exit 77), `SSHTimeoutError`, `SSHConnectionError` (retried
with bounded jittered backoff), `DispatchError`. Configuration lives in
`config/collectors/linux.yaml` (`ssh:` block); reuse it rather than duplicating.

## 4. Proposals for the lead

### 4.1 `extorq.collector.gap_detected` from host collectors (affects: lead, A)

The catalog allows only `source_type = extorq.pipeline` for
`extorq.collector.gap_detected`, but producer `linux-ssh-lab-vm-01` is only
authorised for `linux.*` (PLAN §4.3). Without a change the gateway would
reject the gap events the Linux collector is required to emit.
Proposal (either): (a) the producers registry additionally allows
`extorq.pipeline` for every collector producer, restricted to event type
`extorq.collector.gap_detected`; or (b) add the producer's own source types
(`linux.journald`, `linux.auditd`, `macos.unified_log`, ...) to the catalog
entry. B1 emits `source_type = extorq.pipeline` per the current catalog and
also records the gap in `CollectorHealth.details` so nothing is silently lost.

### 4.2 Auditd records outside `extorq_*` keys (affects: lead, C2)

Audit `CONFIG_CHANGE` (rules deleted/changed) and `DAEMON_END` are
defence-evasion signals but no catalog type allows `linux.auditd` for them.
Proposal: allow `linux.auditd` as a source of `system.log.notable`
(or add `audit.config.changed`, category `configuration`).

### 4.3 Account lifecycle (affects: lead, C2)

Inventory diffs see users appear/disappear in `/etc/passwd`, but the catalog
has no account type; B1 currently reports it as `config.file.changed`
(`resource.path=/etc/passwd`, `attributes.users_added/users_removed`).
Proposal: `account.user.created` / `account.user.deleted` (category
`configuration`, source `linux.inventory`).
