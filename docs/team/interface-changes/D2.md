# D2 (security console) interface requests

Last updated: 2026-11-21

## 1. Console secrets and compose wiring (for A: bootstrap + compose.yaml)

The console (`frontend/`) reads every secret from a file path given in an environment
variable; values are never logged or sent to the browser. It needs:

| Env var (frontend container) | Proposed host file (`make bootstrap`, 0600) | Content |
|---|---|---|
| `EXTORQ_API_TOKEN_FILE` | `var/secrets/api_service_token` (same file D1's API reads via `EXTORQ_API_SERVICE_TOKEN_FILE`) | random token, >= 32 chars |
| `EXTORQ_ANALYST_PASSWORD_FILE` | `var/secrets/console/analyst_password` | random password, >= 12 chars (console refuses shorter) |
| `EXTORQ_VIEWER_PASSWORD_FILE` | `var/secrets/console/viewer_password` | random password, >= 12 chars |
| `EXTORQ_SESSION_SECRET_FILE` | `var/secrets/console/session_secret` | random string, >= 32 chars (HS256 cookie signing key) |

Non-secret settings: `EXTORQ_API_BASE_URL=http://api:8000` (required), optional
`EXTORQ_ANALYST_USERNAME` / `EXTORQ_VIEWER_USERNAME` (defaults `analyst` / `viewer`),
`EXTORQ_HTTPS=auto|true|false` (default auto; the compose console is plain HTTP on loopback,
so the cookie is not `Secure` there; set `true` behind TLS).

Proposed `compose.yaml` service (A owns the file):

```yaml
frontend:
  build: { context: ./frontend }
  environment:
    EXTORQ_API_BASE_URL: http://api:8000
    EXTORQ_API_TOKEN_FILE: /run/secrets/api_service_token
    EXTORQ_ANALYST_PASSWORD_FILE: /run/secrets/console_analyst_password
    EXTORQ_VIEWER_PASSWORD_FILE: /run/secrets/console_viewer_password
    EXTORQ_SESSION_SECRET_FILE: /run/secrets/console_session_secret
  secrets: [api_service_token, console_analyst_password, console_viewer_password, console_session_secret]
  ports: ["127.0.0.1:3000:3000"]
  networks: [edge]
  read_only: true
  tmpfs: ["/tmp", "/app/.next/cache"]
  cap_drop: [ALL]
  security_opt: ["no-new-privileges:true"]
  healthcheck:
    test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:3000/healthz').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"]
    interval: 15s
    timeout: 5s
    retries: 5
  depends_on: { api: { condition: service_started } }
```

The image runs as uid 1001 (`nextjs`); the mounted secret files must be readable by that
uid (see the verification note in `docs/team/status/D2.md`).

## 2. Analyst API (D1)

No change required: the console consumes `docs/api/openapi.json` as published (generated
types in `frontend/src/lib/api/openapi.d.ts`; `frontend/src/lib/api/contract-check.ts` fails
`pnpm typecheck` if a field the console uses is removed or retyped). Notes for D1:

- Asset ids are sent percent-encoded as one path segment (`/api/v1/assets/github%3Aowner%2Frepo`);
  this relies on the `{asset_id:path}` route, which is already in place.
- `POST /alerts/{id}/summary` is called without a body and with a 90 s timeout
  (`EXTORQ_SUMMARY_TIMEOUT_MS`); 409/429/503 `detail` strings are shown to the analyst.
- `POST /alerts/{id}/state` sends `expected_updated_at` (from `analyst_state.updated_at`) so a
  concurrent change produces 409 rather than a silent overwrite.
