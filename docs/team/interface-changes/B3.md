## B3-IC-1 Allow `macos.unified_log` as a source of `auth.ssh.*` (owner: lead; affects C2)

**What.** Add `SourceType.MACOS_UNIFIED_LOG` to the `sources` of
`auth.ssh.login_failed`, `auth.ssh.invalid_user` and `auth.ssh.login_succeeded`
in `contracts/catalog.py` (and optionally `auth.ssh.preauth_closed`,
`auth.ssh.max_auth_exceeded`).

**Why.** macOS Remote Login is OpenSSH; its unified-log messages
(`process == "sshd" OR "sshd-session"`) have the same text as Linux journald
(`Failed password for invalid user admin from 192.0.2.44 port 51022 ssh2`). Today
the catalog only allows `linux.journald`, so the macOS collector must emit them as
`auth.local.failure` (`attributes.auth_service=sshd`) / `system.log.notable`, and
VM-001-style rules or CORR-002 cannot see SSH brute force against the Mac. The
macOS parser already extracts `actor.name`, `network.src_ip`, `network.src_port`,
`attributes.auth_method`, `attributes.invalid_user`. Once merged B3 switches the
mapping (one table change in `unified_log._classify_sshd`, tests updated).

**Status.** Workaround in place (honest types). Remote Login is off on the
reference host, so no data is lost today.

## B3-IC-2 Collector-reported degraded health (owner: A; SDK)

**What.** Let a collector mark a successful cycle as degraded, e.g.
`ctx.health_status_hint = HealthStatus.DEGRADED` (or `ctx.degraded = "reason"`),
honoured by `CollectorWorker.health_status`.

**Why.** The macOS collector isolates its six sources: when one fails (e.g.
`system_profiler` times out) the cycle still succeeds and the runner reports
`ok`. The failure is visible only in `details.sources` / `details.source_errors`.
A first-class `degraded` would make partial failures visible on dashboards.

## B3-IC-3 `CollectorContext.store.snapshot()` is used read-only (owner: A; FYI)

The macOS collector reads the committed snapshot (`ctx.store.snapshot(name)`)
in two places: to carry over items of an unreadable launchd directory (so
"unreadable" never looks like "deleted") and to keep each service's
`first_seen`. A public read-only accessor on the context (e.g.
`ctx.committed_snapshot(name) -> dict[str, dict]`) would avoid touching `store`.

## B3-IC-4 Shared services interface notes (owner: B1; FYI, no change required)

* macOS adapters `macos-sshd` and `macos-screensharing` are registered in the
  shared registry (`extorq_collectors.macos.adapters`). They match only macOS
  launchd labels (`unit_patterns = ("com.openssh.sshd",)` /
  `("com.apple.screensharing",)`), no products/executables, so `match_adapter`
  can never return them for a Linux candidate.
* The macOS discovery does not use `match_adapter`'s first hit blindly: it accepts
  macOS adapters and PLANNED extension points only; an IMPLEMENTED adapter of
  another platform (e.g. a Linux `ssh`/`nginx`/`systemd` adapter whose
  `executables` contain `sshd`/`nginx`) is reported as
  `attributes.other_platform_adapter` with support `none`, never claimed.
  Suggestion for B1: if Linux adapters declare broad matchers (e.g. a `systemd`
  adapter with `unit_patterns = ("*",)`), keep them specific to systemd unit names
  (`*.service`) so other platforms' candidates are not matched.
* `classify_coverage` treats "adapter enabled, no telemetry yet" as `degraded`.
  For log-based adapters B3 passes the *source freshness* (end of the last
  unified-log window read), not the time of the last event, so an idle but
  watched sshd is `monitored`; `Service.last_telemetry_at` carries the newest
  event actually produced by the adapter. Recommend B1 does the same for sshd on
  Linux (a quiet sshd is not a degraded one).
* A service that is installed but not running (e.g. Remote Login off: launchd
  job not loaded) needs a coverage state the helper does not model; B3 returns
  `(IMPLEMENTED, UNMONITORED, "<service> is off: ... not loaded ...")` itself.

## macOS collector section for `collectors/AGENTS.md` (B1 / lead to merge)

### macOS collector (owner B3)

* Native process on the host: `uv run extorq-collect run --only macos-workstation-01`
  (config `config/collectors/macos.yaml`, docs `docs/telemetry/macos.md`). Runs as the
  logged-in user; never sudo, never Full Disk Access, never a configuration profile.
* Commands only through `extorq_collectors.macos.commands.run_command`: absolute
  allow-listed executables, argv lists, minimal env, timeouts, bounded output, and a
  read-only sub-command policy (e.g. `launchctl` may only `print`). Add a new command
  by extending `ALLOWED_EXECUTABLES` *and* `check_read_only_policy`, with a test in
  `tests/unit/macos/test_macos_commands.py`.
* Six sources (unified_log 60 s, launchd 60 s, inventory+services 300 s, posture 300 s,
  applications 3600 s, asset 300 s), each committed by its own `ctx.emit`; a failing
  source calls `ctx.discard_staged()` and never advances a snapshot. One instance per
  state directory (flock).
* Unified-log predicates are fixed fragments in `unified_log.PRODUCERS`; configuration
  selects names only. `<private>` values are never recovered.
* Known platform behaviour (macOS 27): `netstat` returns an empty socket table to
  descendants of ad-hoc signed binaries (the uv CPython); the collector falls back to
  `lsof` (current user's processes only) and reports the gap. `proc_pidpath` and
  `launchctl print` work unprivileged.
* Fixtures (`tests/fixtures/macos/`) are real captures with the account name replaced by
  `testuser`; synthetic records are labelled `extorqSynthetic`; launchd `environment`
  blocks are removed from fixtures.
* MAC-001: `simulations/macos/mac_001_launchagent.sh` (never loads the job; cleanup
  verifies removal).
