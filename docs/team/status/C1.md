### 2. HIGH per-commit isolation (done)
- `_commit_records_isolated`: `GitHubUnauthorized` / `GitHubRateLimited` re-raised; any other
  `GitHubApiError` affects only that commit. Permanent (4xx, oversized/malformed) ->
  `extorq.collector.gap_detected` `gap_reason=commit_unavailable` (github.repository,
  github.commit_sha, attributes `http_status`, `error_type`, `endpoint`, `branch`, `attempts`,
  `transient`; identity `gap:commit_unavailable:<sha>`), checkpoint moves past it.
- Deliberate refinement: transient (5xx/408/network after the client's 3 attempts) -> the
  checkpoint also moves past it at once, but the commit is kept in a bounded retry set in the
  checkpoint (`RepoState.commit_retries`, max 32) and retried once per later poll with its
  genuine push time; after 3 polls the same gap event is emitted. Reason: a single GitHub 502
  must not permanently lose a GH-001 escalation commit. Records per commit are all-or-nothing.
- Per-branch isolation in `poll()`: a compare/listing failure keeps that branch's checkpoint
  while other branches and runs / posture / alerts still run (poll `incomplete`; cycle error
  text now "no repository was polled completely").
