## 1. Identity inventory

### 1.1 ClickHouse users (`infra/clickhouse/migrations/0002_rbac.sql`, `0004_services.sql`, `0005_findings_services.sql`, `0006_refresh_views.sql`)

All service users authenticate with a password stored in
`var/secrets/clickhouse/<user>_password` (0600, generated by
`scripts/bootstrap.py`, passed to containers as compose file secrets). Every
service user is restricted to `HOST IP` 127.0.0.1, ::1 and RFC 1918 ranges
(connections arrive from Docker's private addresses).

| User | Capabilities | Profile / limits | Used by | Rationale |
|---|---|---|---|---|
| `default` | none: removed from the network (built-in user disabled) | n/a | nobody | no passwordless access |

### 1.2 Producer tokens (`scripts/bootstrap.py` `PRODUCERS`, `backend/src/extorq/ingest/registry.py`)

Tokens: 256-bit random, one file per producer
`var/secrets/tokens/<producer_id>.token` (0600). The gateway stores only
SHA-256 digests (`var/secrets/producers.json`) and compares the presented
token against every digest with `hmac.compare_digest`. Every record is
authorised by kind, asset pattern (`fnmatchcase`) and source type; a denial
rejects the batch (`403`) and writes `ingest_audit`.

| Producer | Kinds | Source types | Assets | Holder |
|---|---|---|---|---|
| `macos-workstation-01` | telemetry kinds + `service`, `service_instance` | `macos.*` | `macos:workstation-01` | macOS collector |
| `linux-ssh-lab-vm-01` | telemetry kinds + service kinds | `linux.*` | `linux:lab-vm-01` | Linux SSH collector (on the Mac, never on the VM) |
| `k8s-inventory-extorq-lab` | telemetry kinds + service kinds | `k8s.api_inventory`, `k8s.events`, `k8s.posture` | `k8s:extorq-lab*` (cluster and `.../node/<name>`) | inventory collector |
| `k8s-otel-extorq-lab` | `event`, `collector_health` | `k8s.audit`, `k8s.container_log` | `k8s:extorq-lab`, `k8s:extorq-lab/node/*` | OTel DaemonSet (Secret in `extorq-system`) |
| `github-collector` | telemetry kinds | `github.*` | `github:*` | GitHub collector |
| `scanner-runner` | asset, finding, scan_run, collector_health | `scanner.*` | `macos:workstation-01`, `linux:lab-vm-01`, `k8s:extorq-lab*`, `github:*` | scanners |
| `simulation-runner` | `simulation_run` | `extorq.simulation` | same four patterns | simulation scripts |
| `extorq-selftest` | `collector_health` | `extorq.pipeline` | `macos:workstation-01` | SDK heartbeat self-test (`make sdk-selftest`) and `make demo-check` (`/v1/status`) |

Telemetry kinds = event, asset, inventory_item, finding, scan_run,
collector_health. A `service_instance` without `asset_id` is quarantined
(`asset_unattributable`) because its asset cannot be authorised. A `service`
whose `service_id` does not equal `service_id(asset_id, service_kind,
service_key)`, or an instance whose `instance_id` does not derive from its own
parts, is quarantined as `identity_mismatch` (F-19 gateway part; verified by
`tests/security/test_security_service_identity_binding.py`).

## 3. Container hardening (`compose.yaml`)

All services: `cap_drop: [ALL]`, `no-new-privileges`, json-file logs capped at
3 x 10 MB, images pinned by digest (or built from pinned bases).

| Service | User | Read-only root FS | Memory / pids | Networks |
|---|---|---|---|---|
| clickhouse | 101:101 (server started directly, no root entrypoint) | yes (+ tmpfs `/tmp`) | 3 GiB / 2048 | data |
| migrate, writer, detector | 10001:10001 | yes | 256-512 MiB / 256 | data |
| ingest | 10001:10001 | yes | 512 MiB / 256 | edge |
| api, ai-worker | 10001:10001 | **no**: compose copies `environment:`-sourced secrets (the AI keys from `.env`) into `/run/secrets`, which a read-only root filesystem refuses; code and virtualenv stay root-owned, `/tmp` is a 64 MiB tmpfs | 512 MiB / 256 | data, edge |
| frontend | 1001:1001 | yes (+ tmpfs cache) | 512 MiB / 256 | edge |
| grafana | 472:0 | yes | 512 MiB / 256 | data, edge |
| clickhouse-debug | 65534:65534 | yes | 64 MiB / 64 | data, edge |

The backend image runs as `USER 10001:10001` and installs dependencies with
`uv sync --frozen` from `uv.lock` (`backend/Dockerfile`). Kubernetes workloads:
see T05 (OTel runs as UID 0 with all capabilities dropped, read-only root
filesystem and `RuntimeDefault` seccomp; documented accepted risk).

## 4. TLS boundaries

| Hop | Protection |
|---|---|
| collectors, scanners, OTel -> gateway | HTTPS with the ExtorQ CA (`var/tls/ca.crt`) pinned by clients; bearer token |
| console browser -> frontend | plain HTTP on loopback (residual, known limitation P6) |
| frontend -> API, services -> ClickHouse | plain HTTP inside Docker networks (`edge`, internal `data`) |
| collectors -> GitHub, AI providers | public TLS with system trust; timeouts and bounded retries |
| Mac -> VM | SSH with a pinned host key |
| Mac -> kind API | TLS with the cluster CA from the kubeconfig |

## 5. Data retention (ClickHouse TTLs)

| Table | TTL |
|---|---|
| `events` | 90 days (`event_time`) |
| `inventory_items`, `collector_health`, `rule_runs`, `ingest_quarantine`, `services`, `service_instances` | 30 days |
| `finding_observations` | 180 days |
| `ingest_audit` | 90 days |
| `pipeline_health` | 14 days |
| `analyst_actions` | 365 days |
| `assets`, `alerts`, `alert_evidence`, `investigation_contexts`, `context_relationships`, `ai_assessments`, `analyst_state`, `scan_runs`, `detection_rules` | no TTL (latest-state and audit records) |

ClickHouse `session_log` keeps login attempts for 30 days
(`infra/clickhouse/config.d/20-extorq-system-logs.xml`). The gateway
quarantines events more than one day in the future (`time: event_time_in_future`)
and events older than the 90-day `events` retention (`older_than_retention`).
It exposes the configured acceptance bounds in `/v1/status`. Alert references
outlive raw event retention. Store recovery copies on a private encrypted
filesystem and review them separately because the ClickHouse TTL only acts
on live data. [Retention and recovery policy](recovery.md)

## 6. Logging hygiene

* Structured JSON logs (`extorq.common.logging`); tokens, passwords, keys,
  Authorization headers and prompt bodies are never logged.
* The gateway redacts secret patterns in every free-text field of every record
  kind before the spool commit (**verified**:
  `tests/security/test_security_ingest_redaction.py`) and stores redaction
  counts in provenance; quarantine excerpts are redacted and bounded.
* Validation errors are summarised without input values.
* The VM dispatcher logs denied commands by hash, never content.
* Command-line secret forms (`--requirepass x`, `redis-cli -a x`,
  `curl -u user:pass`, `PGPASSWORD=x`, `MYSQL_PWD=x`, `--password x`, mysql
  `-px`, `sshpass -p x`) are redacted (F-06 resolved; F probe of `redact_text`
  2026-11-22).
* Dispatcher 1.2.0 returns an executable path where the kernel permits it. The
  collector ignores arguments from older dispatchers. Linux auditd and Linux/macOS
  sudo collectors omit command arguments from stored event payloads and excerpts.

## 7. Secret storage and rotation

* Generated secrets: `uv run python scripts/bootstrap.py` (idempotent; 0600
  files in 0700 directories; atomic writes; nothing printed).
* Rotation: `scripts/bootstrap.py --rotate` (ClickHouse passwords, service
  secrets, producer tokens, gateway certificate; restart affected services and
  collectors afterwards) and `--rotate-ca` (new CA; re-distribute `ca.crt` to
  collectors and the cluster). Not exercised by F.
* The user's `.env` is never read or modified by ExtorQ tooling; keys reach
  containers as file secrets.
* Repository hygiene: `.gitignore` covers `.env*`, `var/`, keys, tokens and
  kubeconfigs; `.dockerignore` excludes `.env` and `var/` (**verified**:
  `tests/security/test_security_repo_hygiene.py`); gitleaks over committable
  files and history (`tests/security/test_security_secret_scan.py`).

## 8. Supply chain

Images pinned by digest (ClickHouse, socat, Python, uv, kind node, OTel,
scanners, gitleaks); Python dependencies locked in `uv.lock` and installed
frozen; frontend dependencies locked by pnpm with build scripts denied; the
Ubuntu cloud image verified by OpenPGP signature and SHA-256. CI
(`.github/workflows/ci.yml`) uses `permissions: contents: read`, actions pinned
to full commit SHAs, `persist-credentials: false`, gitleaks over the full
history and Trivy filesystem scans (verified by
`tests/security/test_security_ci.py`).

## 9. Service-aware monitoring (schema 1.1)

* Service records are authorised like other records (producer kinds include
  `service`, `service_instance` for the host and Kubernetes inventory
  producers only).
* Instances without an asset are quarantined (`asset_unattributable`); the
  gateway recomputes `service_id` and `instance_id` and quarantines mismatches
  (`identity_mismatch`). Open (D1): the API still reads a service's instances
  and events by `service_id` alone, so an authorised producer can attach an
  instance on its own asset to another asset's service id (F-19 API part); the
  detector and the correlation builder already check the asset (C2).
* Adapters declare `never_collects`; the security suite enforces data
  minimisation minimums and that planned adapters stay silent
  (`tests/security/test_security_service_adapters.py`).
* Grafana gains only the non-sensitive service columns of `events`.
